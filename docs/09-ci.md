# CI and releases

## Continuous integration

Pushes to `main` and pull requests run the Python secret-shape guard, Ruff and the test
suite. Tests use mocked provider responses; CI does not call the live Gemini API.

## Tagged releases

A `vMAJOR.MINOR.PATCH` tag starts the release workflow. It validates the tag against both
`pyproject.toml` and `packaging/npm/package.json`, builds the Python distribution, publishes
it to PyPI through trusted publishing, publishes the npm bootstrap package with provenance,
and runs a consumer smoke check against the public registries. The configured deployment
job runs only after the package release starts successfully.

Release checklist:

1. Update the Python and npm package versions together using SemVer.
2. Run `uv lock`, `uv run pytest`, `uv run ruff check .`, `uv build`, and the secret guard.
3. Commit with a Conventional Commit message and push the release commit.
4. Create and push the matching `vX.Y.Z` tag; monitor the release workflow to completion.

Never store registry credentials in source. PyPI uses its trusted-publisher integration;
any npm credential belongs in the repository's Actions secret store, not in a workflow file.
