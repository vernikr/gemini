# CI and releases

## Continuous integration

Pushes to `main` and pull requests run the Python secret-shape guard, Ruff, pytest, and the
npm launcher tests (Node 22). Tests use mocked provider responses; CI does not call the live
Gemini API.

## Tagged releases

A pushed `vMAJOR.MINOR.PATCH` tag starts the release workflow. It validates the tag against
both `pyproject.toml` and `packaging/npm/package.json`. For each registry, it checks whether
the exact version is already available and skips publishing it when present. Missing Python
releases are built and published to PyPI through Trusted Publishing; missing npm bootstrap
packages are published with provenance. The workflow then runs consumer smoke checks against
the public registries. Production deployment runs after the PyPI job succeeds.

PyPI Trusted Publishing must be configured for owner `vernikr`, repository `gemini`, workflow
`.github/workflows/release.yml`, and environment `pypi`. npm publishing uses the repository's
`NPM_TOKEN` Actions secret.

Release checklist:

1. Update the Python and npm package versions together using SemVer.
2. Run `uv lock`, `uv run pytest`, `uv run ruff check .`, `npm test --prefix packaging/npm`, `uv build`, and the secret guard.
3. Commit with a Conventional Commit message and push the release commit.
4. Create and push the matching `vX.Y.Z` tag; monitor the release workflow to completion.

Keep registry credentials in the repository's Actions secret store, not in source or workflow
files.
